# CPTool 开发阶段与验收清单

日期：2026-11-17。状态：设计已确认，实施计划待审阅。依据：[工程设计规格](superpowers/specs/2026-11-17-cptool-design.md)。

本文件描述里程碑和交付证据，不代替[逐任务实施计划](superpowers/plans/2026-11-17-cptool-implementation.md)。用户审阅计划后，由助手在当前对话中执行；本阶段不开始应用编码。

## 阶段 0：验证双内核和互操作基础

- [ ] 构建当前 etcpak，记录编译器、依赖、CPU 架构和可分发依赖。
- [ ] 确定可用 PVRTC 编码器及版本，验证 macOS 架构、最低系统和运行方式。
- [ ] 核实 PVRTC 编码器分发条件，确认安装后可用的交付方式。
- [ ] 分别编码并解码全部 16 个模式，记录命令、输入、输出和限制。
- [ ] 验证 PVRTC 的尺寸、质量、Alpha、Mipmaps 行为，将结果固化为能力表。
- [ ] 获取可合法使用的小型 TexturePacker 普通/加密样本，建立 Cocos 解码验证工具。

交付：可重复的能力探测记录、依赖/许可清单、版本固定方案、互操作样本说明。PVRTC 无可交付路径时先解决该问题，不以只显示格式菜单替代功能。

## 阶段 1：工程骨架和资源探测

- [ ] 创建 Electron/React/TypeScript/Vite 工程，React + 手写 CSS。
- [ ] 建立受限 preload/IPC 和文件选择接口。
- [ ] 建立共享能力模型、请求校验和结构化错误。
- [ ] 实现图片/纹理探测、递归扫描、符号链接规则、去重和取消。
- [ ] 建立测试命令、类型检查和桌面启动验证。

交付：macOS 可启动窗口，能导入真实资源并显示正确元数据；异常文件不会使应用崩溃。

## 阶段 2：容器和转换服务

- [ ] PNG/JPEG/WebP 归一化，定义透明、灰度和色彩处理。
- [ ] PKM 1.0/2.0 头、格式映射、长度和逻辑尺寸校验。
- [ ] etcpak 编码/解码适配与 PVRTC 专用适配。
- [ ] 普通 CCZ 与加密 CCZ 编解包、密钥校验及安全存储边界。
- [ ] PVR ↔ CCZ 字节一致性测试；PKM/DDS/PVR 通过独立读取路径验证。
- [ ] TexturePacker → 应用，应用 → Cocos 的双向互操作验证。

交付：通过同一服务接口完成图片编码、PNG 导出、纹理转码和只换容器，形成可自动运行的真实样本矩阵。

## 阶段 3：输出规划和任务队列

- [ ] 原目录与指定目录映射、相对层级及多根冲突处理。
- [ ] 跳过/覆盖/自动重命名；完整识别 `.pvr.ccz` 后缀。
- [ ] 临时输出、成功校验后发布、失败保留原文件。
- [ ] 任务快照、串行重编码、取消、失败重试与结果汇总。
- [ ] 验证同路径转码、Unicode、大小写冲突、目录内输出、权限/磁盘失败。

交付：实际目录批处理可控，不递归处理自己的产物；取消或失败不会留下冒充成功的半文件。

## 阶段 4：React 工作台与真实预览

- [ ] 资源列表、中央对比、右侧参数、底部队列布局。
- [ ] 格式和操作切换时刷新容器、选项和有效性。
- [ ] 实际编码结果预览、请求版本管理、缓存失效和临时数据清理。
- [ ] 缩放、平移、通道、透明背景和尺寸变化提示。
- [ ] CCZ 输入/输出独立密钥、生成/复制和加密状态。
- [ ] 键盘访问、焦点、空/加载/错误状态、窄窗口操作验证。

交付：用户可完整完成导入 → 选择格式 → 检查预览 → 批量输出 → 定位结果；不能用静态示例图代替真实结果。

## 阶段 5：macOS 交付

- [ ] 固定运行时和内核版本，打包所需动态库与许可声明。
- [ ] 分别说明 Apple Silicon 原生、Intel 或 Rosetta 支持的验证结果。
- [ ] 在无开发依赖的环境验证启动、编解码、加密互操作和目录处理。
- [ ] 完成适用的签名/公证，或明确记录尚未具备的交付条件。
- [ ] 保存测试结果、手动验收记录、安装包位置及已知限制。

交付：实际 macOS 安装包与可复现验收证据。Windows/Linux 在后续平台阶段单独验证。

## 执行与文档管理

优先按阶段顺序推进；容器、内核、队列和 UI 之间以共享类型和能力表为契约。关键测试覆盖真实格式和失败边界，避免仅测试组件内部实现。

当前 CPTool 根目录尚无 Git 仓库元数据，已有 `etcpak/` 应单独检查其版本管理状态。实施时先确定根工程的版本管理及上游依赖方式，不把新增应用文件误提交到内核仓库，也不改写上游历史。

仅在本任务实现并验证完成后归档对应 `docs/superpowers/specs/` 和 `plans/` 文件；当前仍在设计阶段，不归档。
