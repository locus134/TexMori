# CPTool 产品与工程设计规格

日期：2026-11-17  
状态：用户于 2026-11-17 确认设计规格；本文件记录设计，不表示功能已经实现。  
项目位置：`/Volumes/zhitai/git/CPTool`

## 1. 目标与设计依据

为游戏资源制作提供本地桌面工具：选择图片或目录，选择纹理编码格式，预览真实编码结果，再批量输出；也能将压缩纹理解码为图片、重新编码或只转换外层容器。

用户已确认：React + 手写 CSS；先开发 macOS，考虑跨平台；etcpak + PVRTC 专用编码器双内核；ETC 保存为 PKM；PVRTC 支持 PVR/PVR.CCZ；加密 PVR.CCZ 与 TexturePacker 使用兼容处理逻辑。

工程建议：Electron + React + TypeScript + Vite，主进程负责本地资源和任务，渲染进程负责界面。该技术组合是设计建议，随本规格一起审阅。

默认输出语义、首期输入图片类型和界面细节属于本规格提出的具体化方案，不视为用户已经逐条确认。

## 2. 首期范围

### 2.1 包含

- 文件选择、目录选择、拖入文件和目录；目录可递归扫描。
- 资源列表、缩略图、尺寸、编码、容器、文件大小与任务状态。
- 编码、解码导出 PNG、压缩格式间重新编码、PVR/CCZ 外层转换。
- 原图和实际压缩结果的并排/滑动对比，联动缩放和平移、适应窗口、100% 显示。
- 透明棋盘格，RGBA、RGB、R、G、B、A 通道查看。
- 按编码和容器刷新参数、验证尺寸和通道损失。
- 批量队列、取消、失败重试、结果定位与汇总。
- macOS 可安装应用，打包内核和运行依赖的方案经过验证。

### 2.2 首期不包含

图集打包与 plist 生成、在线服务、云同步、自动监听目录、ASTC/Basis 编码、立方体/数组/3D 纹理编辑、完整多层纹理编辑器。读到这些纹理时明确说明不支持，不静默当作普通 2D 图处理。

## 3. 格式与容器

| 编码 ID | 显示名 | 通道 | 位率 | 首期输出 |

| etc1 | ETC1 RGB | RGB | 4bpp | PKM 1.0 |
| etc2_r | EAC R11 | R，unsigned | 4bpp | PKM 2.0 |
| etc2_rg | EAC RG11 | RG，unsigned | 8bpp | PKM 2.0 |
| etc2_rgb | ETC2 RGB | RGB | 4bpp | PKM 2.0 |
| etc2_rgba | ETC2 RGBA | RGBA | 8bpp | PKM 2.0 |
| bc1 | BC1 | RGB | 4bpp | DDS |
| bc3 | BC3 | RGBA | 8bpp | DDS |
| bc4 | BC4 | R，unsigned | 4bpp | DDS |
| bc5 | BC5 | RG，unsigned | 8bpp | DDS |
| bc7 | BC7 | RGBA | 8bpp | DDS |
| pvrtc1_rgb_2 | PVRTC1 RGB 2bpp | RGB | 2bpp | PVR / PVR.CCZ |
| pvrtc1_rgba_2 | PVRTC1 RGBA 2bpp | RGBA | 2bpp | PVR / PVR.CCZ |
| pvrtc1_rgb_4 | PVRTC1 RGB 4bpp | RGB | 4bpp | PVR / PVR.CCZ |
| pvrtc1_rgba_4 | PVRTC1 RGBA 4bpp | RGBA | 4bpp | PVR / PVR.CCZ |
| pvrtc2_2 | PVRTC2 2bpp | RGBA 能力 | 2bpp | PVR / PVR.CCZ |
| pvrtc2_4 | PVRTC2 4bpp | RGBA 能力 | 4bpp | PVR / PVR.CCZ |

BC1 首期按本地 etcpak 实际 RGB 编码路径提供，不承诺 1-bit alpha 编码。上述位率不包含容器、Mipmaps、最小编码尺寸和 CCZ 外层开销。PVRTC2 文件可由应用处理，不代表所有 iOS 设备/图形接口都支持使用它。

现有 etcpak 原生可输出 PVR/DDS，并能识别 PVR/KTX/DDS；它不直接提供 PKM 读写或 PVRTC 编解码。应用需补足相应适配，不可仅更换扩展名。ETC 的临时 PVR 可作为内核与 PKM 适配层之间的内部交换格式。

PKM 只保存单层纹理；选择 PKM 时禁用 Mipmap。首期不将 KTX/KTX2 作为用户可选输出。

## 4. 输入与转换语义

### 4.1 输入

图片首期支持 PNG/JPEG/WebP，通过图片预处理统一为 RGBA PNG 后交给编码器；透明和灰度输入需独立验证。输入色彩转换必须有固定策略，不依赖图片查看器的隐式行为。

压缩纹理首期支持 PKM、DDS、PVR、PVR.CCZ；只有格式矩阵中已支持的有效 2D 纹理允许处理。依据文件内容检测容器，扩展名只作为扫描提示。KTX 为内核已有能力，首期不承诺应用导入。

### 4.2 三类转换

1. 编码：图片 → 解码后的 RGBA 工作图 → 目标编码 → 目标容器。
2. 解码/转码：压缩纹理 → 解密/解包 → 解码工作图 → PNG 或重新编码。
3. 外层转换：PVR ↔ 普通/加密 PVR.CCZ；只处理容器，不解码纹理、不重新有损编码。

压缩后无法还原原图的全部信息；“解码为 PNG”得到压缩后的图像。压缩文件单独导入时，左侧标注“输入纹理解码图”，不能标注为丢失的原始图片。

## 5. 动态参数

| 参数 | 显示/启用条件 | 行为 |
|---|---|---|
| 编码、输出容器 | 编码/转码模式 | 选择项来自统一能力表 |
| 抖动 | ETC1、BC1 | 映射 etcpak `-d` |
| 启发式模式选择 | ETC2 RGB、ETC2 RGBA | 关闭时传 `--disable-heuristics` |
| Mipmap | DDS/PVR/PVR.CCZ 编码 | PKM 时不可用 |
| 输入色彩空间 | 编码/转码 | 明确 sRGB/Linear；etcpak `--linear` 只按其实际用途解释 |
| 质量 | PVRTC 编码 | 按选定编码器版本支持的质量档位显示 |
| Mipmap 滤镜 | PVRTC 且启用 Mipmap | 仅显示编码器实测支持的滤镜 |
| 预乘 Alpha | PVRTC，存在 Alpha | 明确是否预乘，写入适用元数据 |
| 尺寸处理 | 编码/转码 | 保持尺寸、补齐边缘或缩放；不隐式变形 |
| CCZ 压缩等级 | 输出 PVR.CCZ | 0–9，默认 6；与 PVRTC 画质参数分开 |
| 内容加密、密钥 | 输出 PVR.CCZ | 加密启用后必填兼容密钥 |
| 输入密钥 | 检测到加密 CCZ | 与输出密钥独立，允许换密钥 |

格式切换时立即重算可选容器和参数有效性。每种格式可保留会话中的有效选择；隐藏的参数不得进入实际请求。解码和只换容器时隐藏编码参数。后台使用同一能力表再次验证，不能只依赖前端禁用控件。

不暴露内核中没有实际效果的选项，不给 etcpak 虚构质量滑块。benchmark 等内核诊断参数不属于资源输出设置。

## 6. 尺寸、通道和色彩

- etcpak 直接 PNG 路径要求宽高为 4 的倍数。保持尺寸模式下不满足要求的文件标为不可执行；用户可以明确选择边缘复制补齐，或缩放。
- PKM 头分别记录原始逻辑尺寸与编码尺寸；解码导出按逻辑尺寸裁回。DDS 等不具备相同记录方式的输出必须显示实际输出尺寸。
- PVRTC 的幂次、最小尺寸及其他约束按具体编码器和目标模式验证，并写入能力表；不对所有 PVRTC 模式套用同一规则。首期优先保证 PVRTC1 的传统 iOS 资源兼容路径。
- 补齐和缩放均显示前后尺寸；更改画布可能影响图集坐标，应用不代改 plist。
- 含 Alpha 的图片选择不保留 Alpha 的格式时给出明确提示；批处理开始前汇总这些文件，不静默丢弃。
- 标明线性数据与颜色纹理差异。R/RG 用途不自动做亮度转换，默认取原图 R/RG 通道。
- 不虚构原格式无法存储的色彩元数据；PKM 的目标色彩空间约定须在资源使用端保持一致。

## 7. TexturePacker/Cocos 兼容 CCZ

### 7.1 格式

PVR.CCZ 是 PVR 的 CCZ 外层封装。普通 CCZ 使用 zlib 压缩；加密 CCZ 使用 Cocos/TexturePacker 内容保护布局，不用自定义 AES/ZIP 替代。通过文件签名区分普通 `CCZ!` 与加密 `CCZp`，不能通过扩展名判断是否加密。

实现包含头字段和字节序、压缩数据、加密覆盖区间、密钥派生、校验和及版本验证。用户于 2026-11-17 批准以独立格式校验及原版 Cocos 加载验证替代运行 TexturePacker；不再要求 TexturePacker 生成样本作为开发前置条件。不能仅以自家编码器解自家结果作为兼容证据；没有相应样本时不宣称已验证 TexturePacker 来源文件。

### 7.2 密钥

- 输入 32 位十六进制字符串，兼容 128 位密钥；允许粘贴可解析的四段 `0x12345678` 表示，统一显示为规范格式。
- 提供安全随机生成、显示/隐藏、复制；生成值需兼容目标 Cocos 实现的 key-part 限制。
- 界面称“加密密钥”，不把普通文本口令直接转换为未知规则的密钥。
- 可复制四段 `ZipUtils::setPvrEncryptionKey(...)` 接入示例；不把真实密钥写入普通日志、诊断信息或项目配置。
- 默认只在当前会话保存。若提供“记住密钥”，使用系统凭据存储；跨平台适配不可降级为明文保存。
- 输入密钥错误、校验失败、文件损坏分别提供可理解的错误；无法准确区分时标为“密钥不匹配或文件损坏”。

### 7.3 兼容验收

CPTool 生成普通和加密样本 → 未修改的原版 Cocos ZipUtils 解包 → 独立纹理读取/实际显示。独立编译原版 ZipUtils 方法的验证工具可证明容器与加密互操作，但不能代称完整 Cocos 图形引擎已加载；两项证据分别记录。另测错误密钥、截断、非法长度、低于/跨越加密覆盖阈值的文件、CPTool 连续使用不同密钥。PVR → CCZ → PVR 必须字节一致。原版 Cocos 同进程切换密钥的状态行为单独记录，不能用每次新进程验证代替。

该功能面向现有游戏资源兼容，不表述为现代强加密保险库。

## 8. 文件、目录与覆盖

### 8.1 规则

提供“输出到原目录”和“输出到指定目录”。原目录输出保留基础名并使用目标扩展名；指定目录保留相对层级。多个导入根目录发生同名相对路径时，不静默覆盖，执行前列出冲突。

默认保留源图片。“覆盖”指替换已存在的目标文件，不等于删除 PNG 源文件。此解释是本规格建议，需审阅确认。

目标存在时提供跳过、覆盖、自动重命名；默认跳过。用户在本次批次明确选择覆盖后，不逐文件重复确认。禁止把临时中间文件当成最终成功结果。

### 8.2 写入与扫描

- 编码到临时位置，完成校验后发布到最终目标；覆盖失败时保留原目标。
- 输入和输出为同一路径的同格式重新编码必须先完整读取并保留原文件，成功后才替换。
- 目录扫描忽略应用临时文件，不跟随目录符号链接，避免循环；去重真实输入文件。
- 输出目录位于输入目录内时排除该输出子树。输入目录与输出目录相同则按原目录策略处理。
- 扫描结果固定为本次任务快照，不持续把新生成文件加入队列。
- 保留 Unicode、空格及多点文件名；`.pvr.ccz` 作为完整后缀处理。大小写不敏感文件系统下检测目标冲突。

## 9. UI 工作台

### 9.1 布局与视觉

左侧资源列表，中央图片预览，右侧参数，底部批处理状态。以真实纹理预览为视觉中心，不设置无关统计卡片。中性灰界面、透明棋盘、少量蓝色操作强调；成功/警告/失败颜色只表达状态。界面使用中文，编码名保留通用英文。

资源领域语言为纹理、通道、块、编码尺寸、Mip 层、容器与队列。以同步查看同一区域的原图/结果作为核心交互；文件路径采用中间省略和完整提示，尺寸与大小使用稳定数字排版。

样式采用手写 CSS 和统一变量；不使用 Tailwind。遵循用户指定的 UI Skills 路由，已选择 `dammyjay93/interface-design` 作为界面指导。

### 9.2 预览行为

参数变化后明确标记“预览已过期”，经防抖启动当前资源预览。预览必须来自对应内核真实编码并解码的结果。请求取消/替换后，旧结果不得覆盖新选择。

对比支持同步缩放和平移，100% 表示像素比例；可以查看 RGB 和 Alpha。源图尺寸与输出尺寸不一致时标明尺寸和比较区域，不制造像素一一对应的假象。首期预览基础层，Mipmaps 的完整编辑不在范围内。

显示输入文件大小、编码后文件大小、包含外层包装的最终大小以及纹理位率；磁盘体积与 GPU 纹理占用分开标注。首次未生成结果时不显示虚构节省率。原 PNG 可能比 GPU 压缩文件更小，允许显示体积增加。

### 9.3 状态与操作

空列表给出导入入口；扫描中允许取消；文件级显示不支持、待处理、处理中、成功、失败、已取消。批次显示已完成/总数，不能把文件计数伪装为编码器内部精确进度。

支持键盘焦点、可访问标签、可见 focus 状态、禁用原因和减少动态效果偏好。工具栏提供导入、移除、清空、开始、取消、重试失败、在 Finder 显示输出。窗口缩小时允许参数区/列表折叠，保证预览和核心操作可达。

## 10. 工程结构与边界

建议目录：

```text
CPTool/
  etcpak/                    # 已有上游源码，保持独立
  apps/desktop/
    electron/                # 应用生命周期、preload、受限 IPC
    src/                     # React 工作台、手写 CSS
  packages/core/             # 能力表、请求类型、校验、输出计划
  packages/containers/       # PKM、CCZ、容器识别与元数据
  packages/engine/           # 双内核适配、进程、工作图、队列、预览缓存
  scripts/                   # 内核构建、依赖检查、打包
  tests/fixtures/            # 自制小图及可分发兼容样本
  docs/
```

React 仅发出受控操作。preload 暴露窄接口；主进程分配文件标识和访问权限。关闭 Node 集成，启用上下文隔离和适用的沙箱。渲染层不得提交任意可执行文件路径或完整 shell 命令。

内核调用使用参数数组、不启用 shell，限制输入输出目录并处理退出码、崩溃、超时和取消。原生编码在独立进程完成；主进程不做阻塞像素处理。

主数据模型：

- `CodecCapability`：编码 ID、内核、通道、容器、有效选项、尺寸限制、可用状态及原因。
- `Asset`：应用分配 ID、来源根、相对路径、实际容器、逻辑/编码尺寸、通道和文件指纹。
- `ConversionRequest`：输入 ID、操作、目标格式、有效编码选项、输出策略、输入/输出密钥引用。
- `PlannedOutput`：最终路径、冲突行为、尺寸变化、通道损失及校验结果。
- `Job`：请求快照、任务 ID、队列状态、时间、输出与结构化错误。
- `PreviewResult`：请求版本、预览句柄、图像尺寸和实际输出大小。

接口边界：能力服务发现可用编码器；资源服务扫描和探测；规划器无副作用地产生输出计划；队列按计划调用编码器；容器服务封装/解封装；预览服务管理真实结果及缓存。路径、密钥、临时文件由主进程侧管理。

## 11. 双内核集成

### 11.1 etcpak

基于当前源码构建 macOS 可执行文件。现有 CMake 要求 3.29、C++20、libpng，并通过 CPM 获取 Tracy；构建应固定依赖版本，避免使用浮动 master 作为发布依赖。发布包不得依赖用户机器上的 Homebrew 路径。

在应用边界先做尺寸和容器检查，避免上游 assert 直接结束工作进程。etcpak 默认内部多线程，批处理首期一个重编码任务运行，避免多文件与内部线程叠加耗尽资源。

PKM 适配实现明确的头字段/格式映射、有效负载长度和逻辑尺寸；不得将包含 PVR 头的数据直接放进 PKM。输入 PKM 可通过无损内部封装交给 etcpak 解码。

### 11.2 PVRTC

优先评估官方 PVRTexTool 的可用 macOS 版本，实现适配层而非把它的全部 CLI 选项直接搬到 UI。固定版本后，通过实际命令帮助、编码/解码样本和架构检查确定能力。

前置交付必须证明：macOS 可运行的二进制及架构；PVRTC1 四种和 PVRTC2 两种模式的真实编码/解码；质量选项；Mipmaps；尺寸行为；分发许可和运行依赖。历史 macOS 下载不代表当前发行版仍支持 macOS，也不能直接承诺 Apple Silicon 原生支持。

若只有 x86_64 版本，明确验证 Rosetta 的实际可用性与安装依赖；原生 arm64 与兼容运行不得混称。编码器不可用时禁用相应格式并显示原因，不能以 ETC 或其他算法冒充 PVRTC。

应用目标为安装后可用的集成工具。仅选择用户本机外置编码器可以用于开发验证，不作为完整发布验收。不能合法内置时提交替代编码器或正式安装依赖方案供用户决定，不静默缩减范围。

## 12. 任务、缓存与错误

任务状态：待处理 → 处理中 → 成功/失败/已取消。取消后停止后续任务，终止当前工作进程并清理未完成输出；已成功输出保留。退出应用时有正在运行的任务则给出明确选择。

预览采用低优先级请求；批量运行时避免争抢编码资源。缓存键包含源指纹、编码器版本、格式和参数；解密输入还应隔离不同密钥对应的缓存，缓存标识不能泄露原始密钥。会话结束清理临时解密数据。

错误类型至少包括：输入损坏、格式不支持、尺寸不合法、密钥缺失/不匹配、输出冲突、权限不足、磁盘不足、编码器不可用/失败、取消。一个文件失败不会导致整个批次退出。

## 13. 发布与验收

- 首期平台为 macOS；界面和业务逻辑不硬编码 Finder、路径分隔符或 macOS 凭据接口。
- 先确定并记录 Electron 和两个编码器共同可用的 macOS 最低版本与 CPU 架构，再锁定发布目标。未验证前不宣传 universal 支持。
- 发布前完成依赖许可证清单、内核版本固定、动态库检查和干净机器运行验证。签名/公证是否具备账号条件单独记录；未完成时标注安装包状态。
- 逐一验证 16 个编码模式的有效输出、解码尺寸和通道；ETC PKM、BC DDS、PVRTC PVR/CCZ 均应通过独立读取路径验证。
- 通过用户批准的独立格式与 Cocos 路径验证 CCZ 互操作，覆盖错误密钥和更换密钥；完整图形加载与独立方法验证分别记录。
- 验证格式切换、无效参数不传入、取消、失败重试、过期预览、Unicode 路径、同名冲突和覆盖失败保留原文件。
- 构建、类型检查、关键模块测试与真实桌面操作均提供证据；只通过网页演示不能判定桌面应用完成。
